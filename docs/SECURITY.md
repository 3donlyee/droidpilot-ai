# Security Policy

DroidPilot AI controls a real Android device via Accessibility. Misuse or compromise
can lead to unauthorized control of the device, exfiltration of on-screen data, or
unwanted actions in apps (e.g., sending messages, posting to social media, deleting
content). This document defines the threat model, security boundaries, and operational
controls.

---

## Threat model

| Threat | Vector | Mitigation |
|--------|--------|------------|
| Attacker impersonates a device | MITM on Worker → Device WSS | TLS (WSS) + per-device secret (32-byte random, generated at pairing time, never logged) |
| Attacker hijacks a session | Stolen session JWT | 24h expiry + HMAC signature (`DEVICE_AUTH_SECRET`) + KV-backed revocation list |
| Attacker pairs with victim's device | Stolen pairing_code | 10-min TTL on pairing_code + 6-digit PIN space + rate limit (10/min/IP) |
| Attacker abuses `/api/chat` | LLM-driven resource exhaustion | 60 req/min/IP rate limit + `MAX_TOOL_CALLS_PER_TURN=20` + per-tool timeout |
| AI runs dangerous shell command | Prompt injection via app content | Shell command allowlist (SAFE/CONFIRM/BLOCKED) + AI never sees shell output unless it explicitly requested it |
| AI sends sensitive screen data to LLM | Accessibility tree contains PII | All Workers AI calls are within your Cloudflare account; no third-party API key used unless explicitly enabled |
| Secrets leak via source code | Hardcoded credentials in repo | `.gitignore` blocks all secret file patterns + pre-commit grep check (see below) |
| Secrets leak via logs | `console.log(token)` | Logger auto-redacts 16+ known secret field names |
| Secrets leak via Wrangler config | `api_token` in `wrangler.jsonc` | `wrangler.jsonc` contains only `vars` (non-secret); secrets via `wrangler secret put` |
| Reverse engineering APK | Decompiling reveals hardcoded secrets | No secrets in APK; all auth via runtime HTTPS to Worker |

## Secrets management

### What counts as a secret

| Name | Where it lives | How to set |
|------|----------------|------------|
| `CLOUDFLARE_API_TOKEN` | Local env var (for `wrangler deploy`) | Cloudflare dashboard → My Profile → API Tokens → Create Token |
| `CLOUDFLARE_ACCOUNT_ID` | Local env var (optional — wrangler auto-resolves) | Cloudflare dashboard → any domain → Overview → right sidebar |
| `DEVICE_AUTH_SECRET` | Cloudflare Worker secret (encrypted at rest) | `openssl rand -hex 32 \| npx wrangler secret put DEVICE_AUTH_SECRET` |
| `OPENAI_API_KEY` | Cloudflare Worker secret (only if OpenAI provider enabled) | `npx wrangler secret put OPENAI_API_KEY` |
| `device_secret` (per device) | Generated at pairing, stored in Worker KV (hashed) + Android SharedPreferences | Auto-managed |
| `pairing_code` (per pairing) | Generated at pairing, stored in Worker KV with 10-min TTL | Auto-managed |
| `session_jwt` | Generated by Worker, stored in browser localStorage | Auto-managed |
| GitHub PAT | Local env var / credential helper (never in remote URL) | GitHub Settings → Developer settings → Personal access tokens |

### What NEVER goes in source / commits / configs

- API keys (Cloudflare, OpenAI, Groq, etc.)
- `device_secret` values
- `pairing_code` values
- `DEVICE_AUTH_SECRET` value
- GitHub PATs
- Real Worker URLs containing tokens in query strings

### `.gitignore` enforcement

The repo's `.gitignore` blocks:
```
.env, .env.*, !.env.example
.dev.vars, .dev.vars.*, !.dev.vars.example
secrets.json, secrets.yaml
*credentials*, *secret*
*.pem, *.key, *.p12, *.jks, *.keystore
google-services.json
```

### Pre-commit secret scan (recommended)

Add to `.git/hooks/pre-commit`:

```bash
#!/usr/bin/env bash
set -e
if git diff --cached | grep -E "^(\\+.*(sk-[a-zA-Z0-9]{20,}|ghp_[a-zA-Z0-9]{36}|cfk_[a-zA-Z0-9_]{20,}|AIza[a-zA-Z0-9_\\-]{35}|-----BEGIN [A-Z ]*PRIVATE KEY))"; then
  echo "ERROR: Potential secret detected in staged change. Aborting commit."
  exit 1
fi
```

```bash
chmod +x .git/hooks/pre-commit
```

## Network security

- **HTTPS only** — `usesCleartextTraffic="false"` in AndroidManifest.
- **WSS only** — Worker rejects `ws://` upgrade requests.
- **CORS** — In production, set `ALLOWED_ORIGIN` in `wrangler.jsonc` to the exact Web UI origin. The default `*` is for development only.
- **HSTS** — Cloudflare auto-adds HSTS headers for `*.workers.dev` and custom domains.
- **TLS version** — Cloudflare enforces TLS 1.2+ on all Worker endpoints.

## Authentication flow

```
[Android app on first launch]
    │
    │  POST /api/device/register
    │  body: { device_name, model, android_version }
    ▼
[Worker]
  - generates device_id     (DROID-XXXX, 4 hex chars)
  - generates pairing_code  (6-digit, 10-min TTL in KV)
  - generates device_secret (32-byte hex)
  - stores device_id → { secret_hash, device_info } in KV (permanent)
  - returns { device_id, pairing_code, device_secret }  ← only time secret leaves Worker
    │
    ▼
[User opens Web UI]
  - enters device_id + pairing_code
  - POST /api/device/pair → Worker verifies code (KV lookup + TTL check)
  - Worker issues session JWT (HMAC signed with DEVICE_AUTH_SECRET, 24h exp, contains deviceId)
  - returns { jwt, device_info }
    │
    ▼
[All subsequent calls]
  Authorization: Bearer <jwt>
  - Worker verifies HMAC, checks exp, checks revocation list (KV)
  - Resolves to deviceId, routes commands via WSS to that device
```

### Pairing code properties

- **Length:** 6 digits (10^6 = 1,000,000 space)
- **TTL:** 10 minutes
- **Single-use** — invalidated immediately after successful pairing
- **Rate limit:** 10 pair attempts / min / IP (KV token bucket)
- **Lockout:** After 5 failed pair attempts on a single `device_id` within 5 min, that device is locked out for 15 min

### Session JWT properties

- **Algorithm:** HMAC-SHA256 via Web Crypto API
- **Key:** `DEVICE_AUTH_SECRET` (32-byte hex, stored as Worker secret)
- **TTL:** 24 hours
- **Payload:** `{ deviceId, iat, exp }`
- **Storage:** Browser localStorage (MVP) — for higher security, switch to HttpOnly + Secure + SameSite=Strict cookie set by Worker

### Secret rotation

- `DEVICE_AUTH_SECRET` can be rotated at any time. All existing sessions immediately become invalid (JWT signatures won't verify).
- `device_secret` per device can be rotated by re-pairing: in the Android app, "Reset pairing" deletes the local secret and calls `/api/device/register` again, generating new credentials.

## Tool execution policy

### Tool allowlist

The Worker only routes tools that appear in `worker/src/tools/registry.ts`. Unknown tool names are rejected with `403 Unknown tool`.

### Shell command policy

`run_shell` commands are classified by the Android-side `CommandValidator`:

| Policy | Action | Examples |
|--------|--------|----------|
| `SAFE` | Execute immediately | `getprop`, `pm list packages`, `dumpsys`, `input tap`, `input swipe`, `settings get`, `am stack list` |
| `REQUIRES_CONFIRMATION` | Show Android dialog → user taps Approve/Reject | `pm clear <pkg>`, `settings put`, `am force-stop`, `input text <sensitive>`, `pm grant`, `pm revoke` |
| `BLOCKED` | Reject before any side effect | `rm`, `rm -rf`, `factory reset`, `reboot`, `shutdown`, `mkfs`, `dd if=`, `flash`, `su -c`, `magisk`, `recovery`, `fastboot` |

> **Note:** In the MVP, `REQUIRES_CONFIRMATION` returns an error to the Worker — the AI should then ask the user via the chat. Phase 2 will add an Android dialog Activity for in-app confirmation.

### AI cannot bypass the policy

- The AI model emits tool calls. It cannot directly execute shell commands.
- `run_shell` arguments are passed through `CommandValidator.classify()` on the device, **before** the command is sent to `Runtime.exec()`.
- Even if an attacker compromises the AI model (via prompt injection in app content), they cannot run `BLOCKED` commands.

### Screenshot policy

- Screenshots are NOT captured on every operation.
- `take_screenshot` is a tool the AI calls **explicitly** when needed.
- After analysis (returned to AI as base64 in tool result), the screenshot is **deleted** from device memory unless the user requested to keep it.
- The Worker never persists screenshots to KV / R2 — they live in the AI conversation context only for the duration of the turn.

## Data minimization

| Data | Sent to Worker | Sent to AI | Stored in KV |
|------|----------------|------------|---------------|
| `device_id` | yes | no (only in routing logs) | yes (permanent) |
| `device_secret` | only at pairing | never | hashed only |
| `pairing_code` | only at pairing | never | 10-min TTL |
| `session_jwt` | every request | never | never |
| `device_info` (model, OS) | yes | included in system prompt | yes |
| Accessibility tree | yes (from device → worker) | yes (in conversation) | never |
| Screenshots | yes (when requested) | yes (in conversation) | never |
| Shell command output | yes | yes (only when AI called `run_shell`) | never |
| Conversation history | yes (in-memory in AgentEngine) | yes | never (planned: D1 with encryption at rest) |

The Worker keeps conversation history in memory only for the duration of a single chat turn (one SSE connection). It is not persisted unless the user enables conversation history (planned feature).

## Audit logs

The Worker writes structured JSON logs (via `worker/src/utils/logger.ts`) to `stdout`, which Cloudflare captures and makes available via `wrangler tail` and Cloudflare Dashboard → Workers → Logs.

Log fields:
- `ts` (ISO timestamp)
- `level` (info/warn/error)
- `event` (pairing/chat/tool_call/tool_result/error)
- `deviceId` (truncated hash for correlation; never the raw `device_secret`)
- `toolName` (when applicable)
- `durationMs` (when applicable)
- `errorCode` (when applicable)

Secret field names (`secret`, `token`, `apiKey`, `device_secret`, `authorization`, `pairing_code`, `password`, `cookie`, ...) are auto-redacted to `"[redacted]"` before serialization.

## Reporting a vulnerability

If you discover a security issue:

1. **Do NOT open a public GitHub issue.**
2. Email: `security@<your-domain>` (replace with your actual security contact).
3. Include: description, reproduction steps, affected versions, suggested fix.
4. Response time: within 72 hours.

## Operational hardening checklist (production)

- [ ] `DEVICE_AUTH_SECRET` is 32+ random bytes, stored as Worker secret (NOT in `wrangler.jsonc`).
- [ ] `ALLOWED_ORIGIN` in `wrangler.jsonc` is set to the exact Web UI origin (NOT `*`).
- [ ] KV namespace `DEVICE_SESSIONS` is created and `wrangler.jsonc` references its real `id`.
- [ ] Android app installed from a signed release APK (not debug build).
- [ ] Android device has full-disk encryption enabled.
- [ ] ColorOS battery optimization disabled for DroidPilot AI (see DEPLOYMENT.md §2.5).
- [ ] Cloudflare Worker analytics + logs reviewed weekly for anomalies.
- [ ] `DEVICE_AUTH_SECRET` rotated every 90 days.
- [ ] Pre-commit secret scan hook installed (see above).
- [ ] GitHub repo has branch protection on `main` (require PR review).
- [ ] GitHub Actions secrets (if using CI/CD) have minimal-scoped tokens.
